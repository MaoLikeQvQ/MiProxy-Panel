# MiProxy Panel v0.1.1

本版整理工程结构，新增应用内访问认证设置，保留 Web 与 SSH 终端的内核、订阅、节点及规则管理功能。

## 本次变更

- Go 程序入口迁入 cmd/miproxy-panel；后台服务、终端、JSON 契约、YAML 合并和认证分别归入 internal 模块，服务端与终端不再互相依赖。
- 前端按内核、概览、代理组、规则、订阅、日志、配置和访问设置组织；规则编辑表单从 App.vue 拆出，删除不可达的旧页面。
- 新增 Web「访问设置」，支持设置、更改和清除密码；设备终端 miproxy-panel access 可通过私有 Unix Socket 设置或恢复访问，输入隐藏。
- 移除 PANEL_PASSWORD 和 MIHOMO_SECRET 环境变量；已有内核认证由扫描接入获取，面板内核认证从实际 YAML 的 secret 读取。
- 密码记录只保存随机盐与 PBKDF2-SHA256 摘要，文件权限为 0600；未设置密码时仅允许真实本机回环连接与私有 Socket，远程请求保持拒绝。
- 新增 Makefile 和架构约定，同步 Docker、CI、测试与打包路径。发布检查新增访问设置浏览器回归及编译程序的真实认证、私有 Socket 恢复和终端隐藏输入测试。
- README 加入三张 Web / 终端演示截图，补齐完整使用、选包、升级认证迁移和安装包体积说明。

## 从 v0.1.0 升级

**旧密码环境变量不再生效。远程部署升级前，请保留本机或 SSH 访问方式。**

1. 升级后，从设备本机或 SSH 转发打开 Web「访问设置」，设置访问密码；登录用户名为 admin。
2. 无法进入 Web 或忘记密码时，在设备交互终端执行 sudo miproxy-panel access；root 用户无需 sudo。命令通过本机受权限保护的 Unix Socket 修改设置，后台必须已启动。
3. Docker 首次或升级后执行 docker compose exec panel /miproxy-panel access 设置密码，再通过浏览器登录。Docker 端口映射不视为容器回环请求。
4. 密码设置后立即生效，浏览器再次要求认证时输入新密码；清除密码会恢复仅本机访问。
5. 重新检测并选择已有内核即可读取控制接口和密钥，无需再配置 MIHOMO_SECRET。外部内核仍由 Sparkle、ShellCrash、OpenClash 等原应用管理配置和进程。

本版保留安装命令、发布文件名、用户配置与数据路径，不覆盖 v0.1.0 标签。

## 下载文件与大小

| 设备 | 选择文件 | 发布前本地实测 |
| --- | --- | ---: |
| Intel / AMD 64 位 Linux、x86 软路由 / NAS | miproxy-panel_linux_amd64 | 约 9.61 MiB |
| ARM64 Linux / OpenWrt、64 位系统树莓派 | miproxy-panel_linux_arm64 | 约 9.00 MiB |
| Apple 芯片 Mac | miproxy-panel_darwin_arm64 | 约 9.16 MiB |
| Intel Mac | miproxy-panel_darwin_amd64 | 约 9.79 MiB |
| 其他 ARM / MIPS / x86 / RISC-V 设备 | 按 downloads.md 的位数、ARM 版本和字节序选包 | 约 8.69–10.50 MiB |

本版共提供 13 个二进制和 6 个配套文件。二进制内含 Web 与终端，不含 Mihomo、Geo 数据和订阅缓存。正式包以本页文件实际大小为准。Linux / OpenWrt 推荐运行 install.sh 自动选包；离线安装需对应二进制、deploy.tar.gz 与 checksums.txt。usage.md 是可离线阅读的说明，downloads.md 解释全部文件及适用环境。

## 验证范围

发布前本地已通过 Go 竞态测试、Go vet、前端构建与单元测试、五套模拟 API 浏览器回归、13 个目标编译及隔离 ARM64 Linux systemd 安装验收。正式发布工作流还会在原生 amd64 Ubuntu 中重复检查、执行编译程序认证测试和 systemd 安装验收，通过后才公开产物。

OpenWrt 真机、旧 ARM / MIPS 固件和真实流量接管仍需对应设备验证。面板不会自动开启系统代理或透明代理；接入外部内核不改变原应用的配置管理职责。
