# MiProxy Panel Web 设计规范

采用成熟代理客户端的紧凑布局，接近 Surge / Mihomo Party 的清晰层级与集中操作。默认浅色白色工作区、浅灰侧栏，服务运行查看、代理切换和配置管理。浅色、暗色和手机端共用组件结构与状态语义。

## 主题与排版

主题颜色集中在 `src/styles/theme.css`。使用 `--canvas`、`--paper`、`--surface`、`--line`、`--control`、`--heading`、`--ink`、`--muted` 表达内容层级，使用 `--accent`、`--success`、`--draft`、`--error` 表达操作及状态。禁止页面硬编码主题颜色。

中文与英文使用系统无衬线字体，代码、IP、时间和规则表达式使用 `--mono`。正文与常规控件 14px，辅助信息 12px，区块标题 16px，页面标题 20px。数字使用等宽数字特性。

## 尺寸与布局

间距采用 4、8、12、16、24、32px。桌面控件默认 36px 高，圆角 6px，通用面板圆角 10px，密集列表以分隔线组织。手机端常用点击区域达到 44px，输入字号至少 16px。桌面侧栏 184px，工作区依次放页面标题、工具栏和内容。配置操作栏固定在工作区底部。

## 组件与状态

通用输入、选择和下拉菜单使用 Element Plus 与统一共享样式。现有 `.button`、`.icon-button`、`.search-box`、`.view-tabs`、`.table-frame` 等共享样式统一尺寸和主题。业务组件使用 scoped CSS，避免覆盖其他页面。

保留清晰键盘焦点。鼠标点击不产生重复外框。加载保留已有内容，进行中操作显示进度。错误说明失败原因和恢复操作。颜色必须配合文字、图标或选中标记。

## 页面行为

视图标签使用下划线样式。代理组桌面左右分栏，去掉左右面板外框，手机分为组列表和节点详情。测速与切换有独立反馈，失败保留当前真实状态。日志有明确的暂停接收和自动滚动状态。规则使用统一列表展示匹配条件、当前策略和编辑操作，不设置运行规则、配置规则或规则集标签；刷新旁的添加按钮直接打开规则弹窗。保存和排序自动应用，未成功重载或外部配置草稿必须明确提示。规则列表全量显示并在窗口内滚动，拖动手柄和方向键均可排序。订阅规则收纳为保留原顺序和各条策略的子规则组，主列表使用一条引用。订阅规则组在列表内展开查看内容。新规则集默认前置引用。订阅低频删除操作收进更多菜单。配置应用准确区分校验、保存和重载结果。

## 验收入口

`#components` 为组件样板页，展示输入、选择、按钮、标签、主题、弹窗、焦点及加载反馈。验证页面时同时检查浅色、暗色、桌面、手机、长名称、空数据和错误状态。

## 前端目录与职责

- `src/app/App.vue` 负责导航、共享配置草稿和应用结果协调；页面功能放在 `features/`。
- `features/core`、`overview`、`groups`、`rules`、`subscriptions`、`logs`、`configuration`、`settings` 各自维护页面及专属交互。
- `features/rules/RuleEditor.vue` 拥有规则表单状态与弹窗，`ruleForm.ts` 验证输入，应用层负责持久化及内核重载。
- `shared/` 只放跨功能复用的请求、格式化、主题和基础组件；功能专属类型和逻辑留在功能目录。
- `styles/` 保存主题变量及共享布局，单页专有样式尽量留在对应组件。
- `tests/unit` 验证配置转换；`tests/browser` 通过正常页面入口验证交互，API 使用测试数据。
